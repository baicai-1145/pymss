## 3. What this orders the Triton work as (TASK §6)

1. **The time-axis depthwise conv, weight gradient first.** `Conv3DBackpropFilterV2` alone is 0 ms of the 285 ms step (0%), and its sibling `Conv3DBackpropInputV2` is 0 ms. Measured on one conv at the training shape (1488 x 384 x 258, bf16, k=31, groups=384): forward 3.7 ms, dX 8.2 ms, **dW 122.9 ms** - the weight gradient is 33x the forward. This is §6 item 2 (`norm_dwconv`), and on this device it is by far the biggest single line in the step.
2. **The elementwise chains around it.** Mul chains 3 ms, fp32 divs 0 ms, casts 15 ms, adds 26 ms - §6 item 3 (gate/out chains, `BlockFeedForward` silu-mul, `StaticBandMixer` per-head mixing).
3. **Not the audio front end.** STFT 3.4 ms + ISTFT 3.3 ms + mask apply 0.3 ms = 7.0 ms, so §6 item 1 is not worth a kernel yet; the FFT body stays with torch.
4. `masked_loss` is 1.1 ms, so the `torch.quantile` rewrite (§6 item 4) is not a target either.

Backward is 138 ms vs forward 79 ms. That gap is the conv weight gradient above, not attention.
